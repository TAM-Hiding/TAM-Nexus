# Proposed NX-002 · Deterministic coordination prototype

**Status** Specification for a separately authorized work order.

Build one local, single-operator command harness with a SQLite store and fixture evidence. Run one job at a time. Use deterministic fake workers for investigation, implementation, verification and separate review. The “change” is a synthetic fixture result. Facilitating publication means only a fake broker in an isolated test fixture. Archive links are opaque. Use a controllable clock, bounded fixture budgets and injected fault boundaries. The tests should exercise the ordinary command entry point plus a simulated restart. Record reports in machine-readable and human-readable form over the same data.

No network, external repo checkout, real source edits, GitHub credentials, real Archive, LLM, GPU, production sandbox, daemon, production UI, A2A, MCP, SIL or physical system belongs in this slice. The harness validates policy decisions and effect bookkeeping. It cannot establish real sandbox isolation or provider behavior.

## Acceptance cases

| ID | Test | Observable result |
| --- | --- | --- |
| N01 | Save a conversation, then explicitly submit the HERO-CAD fixture report | Saving conversation schedules zero jobs. Submitted investigation preserves original message ID, verbatim authorized text and pinned fixture ref. |
| N02 | Register eligible/ineligible workers and dispatch | Deterministic eligible selection and recorded lease. A worker advertising capabilities outside policy cannot enlarge scope. Missing capability blocks clearly. |
| N03 | Complete fixture investigation with differing X/Y and X/Y/Z results | Store both observations, command/fixture refs, a hypothesis and limitations. Preserve inconclusive output when fixture evidence is insufficient. |
| N04 | Try implement before approval; try forged worker decision, wrong principal, wrong repo/base or stale proposal | State and synthetic file remain unchanged. Typed denials recorded. Denial closes the order. Proper approval of current proposal enables the exact implementation step. |
| N05 | Revoke or expire approval after queueing and before an effect; try publishing on edit grant | Reject all affected dispatch or effects. Merge and deployment requests always fail. A new valid grant enables only its separately approved operation. |
| N06 | Interrupt an investigation or implementation attempt and restart from a durable checkpoint | Preserve events and budgets, fence prior attempt, reject its late result, avoid rerunning accepted steps and resume the next eligible step. |
| N07 | Duplicate submission, callback or lease claim | Exact command replay returns previous result. Conflicting duplicate is rejected. Only one attempt can commit per generation. Repeated results cannot create a second checkpoint. |
| N08 | Interrupt artifact staging and corrupt or remove a referenced artifact | Failed digest/availability check blocks handoff. Orphan artifacts are never served as evidence. State and its event stay atomic under an injected DB failure. |
| N09 | Inject lost acknowledgement before and after fake branch/PR effect, remote drift between effects, and a mismatched PR reply | Observe accepted effect without duplication. Where outcome remains ambiguous, pause and prevent conflicting effects from another work order on the same target. Drift stops the draft before dispatch and a mismatched reply records an external effect and blocks the intended handoff. No cleanup is dispatched. |
| N10 | Verify, independently review, then change the candidate | A fake reviewer with a distinct identity checks the exact revision. Candidate drift invalidates verification/review for handoff or fake publication. |
| N11 | Export a report and accept or decline the handoff | Report contains original scope, findings, approvals, attempts, counts, review, effects, unknowns and provenance. Redact secrets/private payload. Completion requires authenticated acceptance of the correct exact handoff. A declined handoff retains a link for a new proposal. |
| N12 | Resolve opaque fixture refs with missing, stale, denied and unavailable results | Never collapse a failure into satisfied evidence. Read or report respects policy and any supplied source revision. |
| N13 | Exhaust budget through retries and try restarting | No infinite loop or budget reset. Terminal report carries last checkpoint, known effects and a reason. |

Exit with an offline test command and results, representative machine and operator reports, and independent review. Acceptance should compare the interrupted and successful traces for equivalent intended outcomes and correct additional audit events. Record what remains necessary before proceeding to any real runner or GitHub broker. Do not require real Archive integration to validate recovery.
