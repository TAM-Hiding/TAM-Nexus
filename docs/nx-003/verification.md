## Executed checks

`NEXUS_REQUIRE_LINUX=1 python -m unittest discover -s tests -v` passed **42 tests, zero skips**, from a clean candidate snapshot using Python 3.12.14. The same 42 tests passed in strict mode with Python 3.11.18. This includes all 29 NX-002 tests and 13 NX-003 tests. No fallback implementation was used for the kernel suite.

The test host was x86-64 Linux 6.18.57 with Bubblewrap 0.12.0, util-linux 2.41.5, libseccomp 2.6.0 and distro CPython 3.13.5 inside the sandbox. The test account had no effective host capabilities. No privileged host components or policy changes were needed. The util-linux probe confirmed a different network namespace inode from the calling process. The documented Linux CLI command reached the evidence handoff. The eight checked-in NX-002 example reports regenerated byte for byte. `git diff --check` passed.

## Independent review

A separate read-only reviewer inspected `6261ca44deadd2e36e4779e6e82fd84f34a85588` and rechecked the corrected code on `c695dcc685e252e6b9bc18abdcfcbc9978cc5d93`. The reviewer ran all 42 tests with Linux coverage required and no skips. The review examined mounts, network and syscall controls, descriptors and environment, PID-namespace cleanup, output validation, assumptions about per-process limits, and SQLite races.

| Finding | Correction |
| --- | --- |
| Medium · Exact replay of a fake run could satisfy a later explicit Linux run without launching a sandbox. | Include the Linux profile in run identity without changing legacy fake fingerprints. Persist Linux selection for the work and linked implementation so a later default command cannot fall back. Added replay and recovery regressions. |
| Medium · A fake worker or fake publication could proceed after a durable fence while a Linux supervisor still held its cleanup lock. | Require the same lock for fake execution and mock publication, including after a fence. Distinguish durable cancellation from confirmed process cleanup. Added lock interleaving coverage. |
| Low · Overflowing JSON numbers produced an imprecise supervisor error. | Refuse non-integer JSON numbers in the fixture parser. Added a typed-failure test. |
| Low · Core-dump wording overstated the resource limit. | Clarified that `RLIMIT_CORE=0` covers ordinary core files. A host-configured piped handler may ignore it. |

No code blockers remained. See the [operator guide](README.md) for remaining assumptions and the proposed NX-004 scope.
